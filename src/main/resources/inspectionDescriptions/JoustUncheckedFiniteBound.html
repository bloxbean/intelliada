Reports IntervalLib.finiteUpperBound and IntervalLib.finiteLowerBound compared without a Finite check, inside a class annotated @StateContract.

Both return -1 for an infinite bound, so comparing the result without first checking that the bound is IntervalBoundType.Finite can accept an unbounded validity interval.

This is a heuristic. A call is reported when its value is compared (the receiver or argument of compareTo/equals, or an operand of a relational or equality operator, directly or through a local variable it is stored in) and the enclosing method or initializer never names org.julclang.ledger.IntervalBoundType.Finite (for example in an instanceof or a case pattern).

Advice only: JOUST's build stays the authority (IntelliAda ADR-004 D10).
